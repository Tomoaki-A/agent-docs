# マイグレーション規約

ORM やマイグレーションツールの種類によらず適用される共通規約。
具体的なコマンド名やファイルの配置は各プロジェクト・ORM のものに読み替えること。

## 基本原則

- マイグレーションは原則として ORM/ツールが提供する生成コマンドで自動生成する
- 自動生成されたマイグレーション成果物（SQL・スナップショット・メタデータ等）は手動で編集しない
- スキーマ定義を変更したら、必ず生成コマンドを実行してマイグレーションを再生成する
- AI は自動生成物を手書きで修正してはならない。修正が必要な場合はスキーマ定義を直してから再生成する

## 手動マイグレーションが必要なケース

自動生成では表現できない、以下のような変更でのみ手動マイグレーションを作成する。

- 既存データのバックフィル（例: 新カラムに既存データを埋める）
- NOT NULL 制約の段階的な追加（バックフィル → 制約追加の2段階）
- カラムやテーブルのリネーム（ツールが DROP + CREATE と解釈してしまう場合）
- データ変換を伴うスキーマ変更（型変更に伴う値の移行など）

## 手動マイグレーション作成手順

1. まず生成コマンドで直前までの自動生成マイグレーションを作成済みであることを確認する
2. ツールの規約に従った命名・配置で手動マイグレーションファイルを追加する
   - 連番・タイムスタンプ等の採番規則はツールのものに従う
3. ツールがスナップショットやメタデータを管理する場合は、対応するファイルも整合性を保って追加・更新する
   - 識別子（ID 等）は新規に採番し、直前の状態へのリンク（前方参照）を正しく設定する
   - 既存定義をベースにコピーし、必要な差分のみを加える
4. ツールが提供する整合性チェックコマンドでチェーン・履歴の整合性を検証する

## コンフリクト発生時の対応

- マイグレーションの採番やスナップショットがコンフリクトした場合、成果物を手で編集して無理に解決しない
- 自分の変更を一度取り下げ、最新の状態を取り込んだ上で生成コマンドを再実行してマイグレーションを作り直す
- リネームやバックフィル等の手動マイグレーションは、再生成後の最新の連番・履歴に合わせて作り直す

## 禁止事項

- 既存スナップショット／メタデータの識別子・前方参照を書き換えてはならない
- 既存のマイグレーション SQL を変更してはならない
- マイグレーション履歴（ジャーナル等）の既存エントリを変更してはならない
- 適用済みのマイグレーションを編集してはならない（修正は新しいマイグレーションとして追加する）
