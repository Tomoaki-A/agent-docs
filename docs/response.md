# 回答フォーマット

## 適用範囲

Claude Code の応答には「実装作業の報告」と「質問・議論への回答」の2種類がある。
このフォーマットは**後者（質問・議論への回答）にのみ**適用する。
実装・タスク実行に伴う進捗報告や成果報告には適用しない。

（サブエージェント間の受け渡しは `formats/*`、コード実装は `rules/*` を参照すること）

## 基本原則

- **結論ファースト**: 最初の一文で結論・答えを述べる。前置きや背景から書き始めない。
- **構造は「結論 → 根拠 → 詳細」**: 必要な深さまでで止め、聞かれていない情報を足さない。
- **簡潔さ優先**: 質問の粒度に長さを合わせる。単純な質問には単純に答える。

## 禁止事項

- だらだらとした前置き（「ご質問ありがとうございます」「〜について説明します」等の本題前の定型文）
- 聞かれていない背景説明・周辺知識の列挙
- 直前に述べた内容の不要な要約・繰り返し
- 過剰な相槌・謝辞・自己言及

## 構造テンプレート

```md
<結論を1〜2文で>

## 理由 / 詳細（必要な場合のみ）
- <根拠や手順を箇条書きで>
```

- 1行で答えられる質問は、見出しも箇条書きも使わず1行で返す。
- コードや手順が答えそのものになる場合は、説明を最小化してコード・手順を主役にする。

## 例外ケース

結論を先に出せない／出すべきでない場合がある。以下では選択肢や前提の提示を優先する。

- **設計・方針の提案**: 複数案のトレードオフを並べる必要があるとき。ただし推奨案を最初に明示する。
- **曖昧な要求**: 前提が複数あり得るとき。結論を断定せず、確認すべき点を先に示す。
- **調査結果の報告**: 事実を列挙する性質のとき。それでも「要点 → 詳細」の順は守る。

## 良い例 / 悪い例

悪い例:

```
ご質問ありがとうございます。この機能について説明する前に、まず背景を
お伝えします。一般的に〜という考え方があり……（中略）……したがって、
答えは A です。
```

良い例:

```
答えは A です。

理由は B だからで、C のケースでは D に注意する必要があります。
```
