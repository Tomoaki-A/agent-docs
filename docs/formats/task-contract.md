# Task Contract フォーマット

architectサブエージェントが出力する設計契約のテンプレート。

## 並列実行計画（Parallel Plan）の記述ルール

- 並列単位の識別子は A, B, C, D, E のアルファベット順で定義する（最大5つ）
- `after: なし` は依存なし（即時起動可能）を意味する
- `after: A` は並列単位Aの全 items 完了後に起動することを意味する
- `after: A, B` のようにカンマ区切りで複数指定可能
- `items` に記載する作業名は Work Items に記載した作業名と**完全一致**させること
- 同一ファイルを複数の並列単位の items に含めてはならない
- Work Items に定義したすべての作業名が、いずれかの並列単位の items に含まれること

---

```md
Task Contract（設計契約）

目的（Goal）:
- <このタスクで達成する内容を1〜3行で明確に記述する>

非対象（Non-Goal）:
- <このタスクでは実施しない内容を記述する>

変更範囲（Scope）:

含める（Included）:
- <変更対象のファイル・ディレクトリ>

含めない（Excluded）:
- <変更を明示的に禁止するファイル・ディレクトリ>

作業単位（Work Items）:

1. 作業名: <作業名を記述する>
   概要:
   - <何を・どのように実装するかを記述する>

   対象ファイル:
   - path/to/file
   - path/to/file

2. 作業名: <作業名を記述する>
   概要:
   - <何を・どのように実装するかを記述する>

   対象ファイル:
   - path/to/file

並列実行計画（Parallel Plan）:
- 並列単位 A:
    after: なし
    items: [<作業名>, <作業名>]
- 並列単位 B:
    after: A
    items: [<作業名>]
- 並列単位 C:
    after: A, B
    items: [<作業名>]

完了条件（Definition of Done）:
- [ ] <これを満たせば完了とみなす条件を記述する>

リスク（Risks）:
- <既存機能・依存関係・並列実行などの観点で注意すべきリスクを記述する>

未解決事項（Open Questions）:
- <不明点がある場合は記述する。なければ「なし」>
```
