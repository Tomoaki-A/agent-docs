# Design Review Result フォーマット

reviewerサブエージェントが出力する設計レビュー結果のテンプレート。

## 重要度の定義

| 重要度 | 定義 | PM の扱い |
|--------|------|-----------|
| **Must** | 修正しないと実装に進めない。Goal 未達・スコープ不備・ファイルパス誤り・並列計画の競合・既存設計との重大な不整合等 | architect が修正 → 再レビュー必須 |
| **Should** | 修正すべきだが Must より優先度は低い。設計原則の軽微な逸脱・リスク記載漏れ・DoD の不足等 | architect が修正 → 再レビュー必須 |
| **May** | 改善提案。より良い設計アプローチの提案・命名の改善等 | 完了報告に記録のみ、対応不要 |

---

```md
## レビュー結果サマリー
<問題なし / May のみ / Should あり / Must あり> の4段階で判定

## 指摘一覧
レビュー結果を指摘の数だけ下記形式でリスト化する

| 重要度 | 対象セクション | 内容 | 修正提案 |
|--------|---------------|------|----------|
| Must / Should / May | Task Contract のセクション名 | 何が問題か | どう直すか |

## 総評
<担当観点から見た設計全体の品質評価を2〜3文で記述する>
```
