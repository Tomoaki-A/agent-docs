# Reviewer Result フォーマット
architectサブエージェントが出力する設計契約のテンプレート。

## 重要度の定義

| 重要度 | 定義 | PM の扱い |
|--------|------|-----------|
| **Must** | 修正しないと完了不可。バグ・仕様違反・Scope 外変更・セキュリティホール・設計上の問題・既存との不整合等 | engineer が全件修正 → 再レビュー必須 |
| **Should** | 修正必須だが Must より優先度は低い。パフォーマンス懸念等 | engineer が全件修正 → 再レビュー必須 |
| **May** | 改善提案。可読性・一貫性・ベストプラクティスへの軽微な逸脱等 | 完了報告に記録のみ、対応不要 |

## レビュー結果サマリー
<問題なし / May のみ / Should あり / Must あり> の4段階で判定

|--------|----------------|------|----------|
| Must / Should / May | path/to/file:L00 | 何が問題か | どう直すか |
