# /create-issue - Issue 設計スキル

ユーザーのざっくりしたアイデアを対話的に深掘りし、実装者に意図が明確に伝わる高品質な GitHub Issue を作成する。

## このスキルの目的

- 曖昧な要望を **1トピックずつ質問** して具体化する
- 考慮漏れを防ぎ、実装者が迷わないレベルまで要件を明確にする
- 最終的に `/github issues create` で Issue を作成する

## 禁止事項

- 複数のトピックをまとめて一度に質問しない（1トピック1質問を厳守）
- 推測で仕様を決めない（必ずユーザーに確認する）
- 詳細な技術設計（命名・アーキテクチャ・実装方法）には踏み込まない
- Issue テンプレートの各セクションを勝手に埋めない

---

## Issue テンプレート（最終出力フォーマット）

```markdown
## 概要
<!-- 何を実現したいか。1-2文で簡潔に -->

## 背景・動機
<!-- なぜこれが必要なのか。現状の課題や、これがないと何が困るか -->

## ゴール
<!-- この Issue が完了したとき、何が達成されている状態か -->

## 受入条件
<!-- 具体的な完了基準。チェックリスト形式 -->
- [ ] ...

## 対象範囲

### やること
- ...

### やらないこと
- ...

## 補足・参考情報
<!-- 関連する既存コード、外部リソース、設計上の前提など。必要な場合のみ -->
```

## 実行手順

### Step 1: 受付

ユーザーの `$ARGUMENTS` を受け取り、以下を短く返す：

```
受け付けました: <ユーザーの一言をそのまま記載>

これから何点か質問して、Issue の内容を具体化していきます。
```

### Step 2: 対話による深掘り（1トピックずつ順番に）

以下の順序で、**1トピックにつき1つの質問** を行う。
各質問はユーザーの回答を待ってから次に進む。
回答の内容次第で追加の深掘りが必要と判断した場合は、同じトピック内でフォローアップ質問を行ってよい。

AskUserQuestion ツールを使って質問する。選択肢がある場合は選択肢を提示し、自由記述が適切な場合は選択肢なしで質問する。

#### 質問順序

**Q1. 「何を」の明確化**
目的: 概要セクションの具体化
- ユーザーの一言が指す対象を具体化する
- 「誰が」「何を」「どうする」が分かるレベルまで

**Q2. 「なぜ」の確認**
目的: 背景・動機セクションの具体化
- なぜこれが必要なのか
- 現状の課題は何か
- これがないと誰が何に困るのか

**Q3. ゴール・完了条件**
目的: ゴール・受入条件セクションの具体化
- どうなったら「完了」と言えるか
- ユーザーや利用者が確認できる具体的な状態は何か

**Q4. スコープの境界**
目的: 対象範囲セクションの具体化
- 今回やるべき最小範囲は何か
- 明確に「やらないこと」はあるか
- 将来的にやるが今回は含めないものはあるか

**Q5. 前提の確認**
目的: 補足・参考情報セクションの具体化
- 大前提として知っておくべきことはあるか（既存の制約、外部依存、関連機能など）
- コードベースの調査が必要な場合は、大前提レベルに限定して調査する（詳細設計は不要）

#### 質問のルール

- **1トピック1質問**: 複数の論点を1つの質問に混ぜない
- **重要度順**: Q1 → Q5 の順序を守る
- **深掘り優先**: 回答が曖昧な場合は、次のトピックに進まずフォローアップする
- **スキップ可**: ユーザーが「特にない」「お任せ」と答えた場合は、その旨を記録して次へ進む
- **コンテキスト分離**: 前のトピックの議論が次の質問に不必要に影響しないようにする

### Step 3: Issue ドラフトの作成と確認

すべての質問が完了したら（またはユーザーが「もう十分」と判断したら）：

1. 対話で得た情報をもとに、Issue テンプレートに沿ったドラフトを作成する
2. ドラフト全文をユーザーに提示する
3. 「この内容で Issue を作成してよいですか？ 修正したい箇所があれば教えてください。」と確認する

#### ドラフト作成のルール

- 対話で得た情報のみを使う（推測で補完しない）
- ユーザーが「特にない」と答えたセクションは省略するか「特になし」と記載する
- 受入条件はチェックリスト形式（`- [ ]`）にする
- 簡潔で具体的な表現を使う（冗長な説明は避ける）

### Step 4: Issue の作成

ユーザーが承認したら、`/github` スキルを使って Issue を作成する。

```
Skill: github
Args: issues create "<タイトル>" --body "<ドラフト本文>"
```

タイトルはドラフトの「概要」セクションから簡潔に生成する。

## 出力の言語

ユーザーへの質問・整形結果は日本語で出力する。
